## Estados, evidências e reexecução

| Estado exibido/conceito | Persistência e condição real |
|---|---|
| Rascunho / pronto local | Publicação e MP4 preparados no navegador; direitos/revisão e áudio exigidos. Pronto local não significa enviado |
| Recebido / autorizado | Arquivo foi transferido ao serviço e tem binding de hash, versão, conta, texto, direitos e opções; execução depende de aprovação separada |
| Enviando | uploading, com sessão/offset/lease persistidos. Uma revisão concorrente não substitui tarefa aceita |
| Pendente / aguardando | processing, scheduled, awaiting_user ou retry_wait. Resultado privado/não listado e TikTok inbox não recebem rótulo de publicação pública |
| Confirmação necessária | needs_reconciliation para resposta perdida/inicialização incerta; awaiting_reconnect para permissão/credencial recusada. Não repetir criação remotamente por palpite |
| Falha / rejeitado / cancelado | failed, rejected, cancelled. Cancelar localmente depois de possíveis bytes remotos não desfaz o envio; o código recusa cancelamento enganoso e pede conciliação |
| Publicado confirmado | YouTube processado com privacidade pública e ID/URL; no navegador, registro manual é uma evidência separada ou recibo conciliado e vinculado aos dados atuais. O TikTok não inventa URL pública a partir de PUBLISH_COMPLETE |
| Simulação concluída | simulated_complete com ID e URL externos nulos. Nunca vira publicação real |

Inspeção: server/runtime/contracts.mjs valida payload e binding, ignora campos arbitrários, recusa plataformas sem adaptador; Transfers usa fingerprints e transações para evitar duplicar blocos/tarefas. Store.claim/Worker usam lease exclusivo, revisões, backoff/tentativas limitadas, validade dos direitos e verificação dos bytes. Providers limita hosts HTTPS, recusa redirecionamentos, guarda checkpoints e usa timeout. YouTube consulta a mesma sessão após falha de bloco; sessão expirada ou inicialização desconhecida não inicia outro upload. TikTok com bloco de resultado incerto exige conciliação. app/service.js só incorpora recibo se corresponder à produção/arquivo/aprovação atual.

Não foi acrescentada segunda fila. Testes existentes cobrem essa funcionalidade. Quatro testes de falha adicionais em tests/publication-safety.test.mjs exercitam timeout na inicialização, resposta 200 inválida, credencial fictícia 401 e flags OFF/destinos manuais recusados. Não geram OAuth real, não alteram variáveis operacionais e usam Providers com transporte mockado explícito; flags true aparecem somente nas fixtures em memória para testar os ramos dos adaptadores.

Comandos de teste: node --test tests/server.test.mjs; node --test tests/operations.test.mjs; node --test tests/publication-safety.test.mjs. Regressões UI em Chrome/servidor isolados: publishing.cjs, publication-ui.cjs, server-ui.cjs, operations-ui.cjs. Resultados consolidados em .cache/publication10/ e .cache/publication10-regression/. Falhas de login/permissão são simuladas, não tentativas contra contas do proprietário.
